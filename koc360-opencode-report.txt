# Final Report: Student Client-Side Navigation Loading Fix

## 1. Affected Student Route

**File:** `src/routes/students_.$studentId.tsx`  
**Route path:** `/students_/$studentId`  
**Route name:** Student 360 / Student Profile Page

## 2. Root Cause

The route loader was calling `getStudentProfileData(params.studentId)` directly from `@/lib/students/profile.server` without wrapping it in a `createServerFn`. This caused a **server/client boundary violation** during client-side navigation.

The `.server.ts` module imports server-only dependencies (Notion API, environment variables) that are not available in the client execution context. During client-side navigation, the loader attempted to execute server-only code without proper server boundary isolation.

## 3. Why Hard Refresh Worked

During hard refresh (initial page load), TanStack Start performs **server-side rendering (SSR)**:
- The loader executes in a full Node.js server context
- All `.server.ts` modules and environment variables are available
- `getStudentProfileData()` can access Notion API and config without issues
- The page renders successfully on the server and hydrates on the client

## 4. Why Client-Side Navigation Failed

During client-side navigation (e.g., clicking a student link from the students list):
- TanStack Start attempts to re-run the loader in the client context
- Without `createServerFn` wrapper, the loader doesn't properly establish the server boundary
- The `.server.ts` module import chain tries to execute in a context where server-only dependencies are unavailable
- This causes the loader to fail or return incomplete data
- The page either shows an error state or loads with missing data

## 5. Same as Session Workspace Bug?

**Yes, this is the exact same pattern.**

Both routes had loaders that directly called `.server.ts` functions without `createServerFn` wrappers:

**Session Workspace (previously fixed):**
```typescript
loader: async ({ params }) => {
  return await getSessionWorkspaceData(params.sessionId);  // ❌ Direct call
}
```

**Student Profile (just fixed):**
```typescript
loader: async ({ params }) => {
  return await getStudentProfileData(params.studentId);  // ❌ Direct call
}
```

Both were fixed by wrapping the server function call in `createServerFn`.

## 6. Exact Fix Applied

Added a `createServerFn` wrapper for the student profile data loader:

```typescript
const loadStudentProfile = createServerFn({ method: "GET" })
  .validator((data: unknown) => {
    if (!data || typeof data !== "object" || !("studentId" in data) || typeof data.studentId !== "string") {
      throw new Error("Invalid studentId");
    }
    return data as { studentId: string };
  })
  .handler(async ({ data }) => {
    return await getStudentProfileData(data.studentId);
  });
```

Updated the route loader to call the server function:

```typescript
loader: async ({ params }) => {
  return await loadStudentProfile({ data: { studentId: params.studentId } });
}
```

This ensures proper server/client boundary isolation during both SSR and client-side navigation.
