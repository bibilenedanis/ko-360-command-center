## 2. Exact Validation Bug Fixed

Two compounding bugs in `validateSessionBelongsToSessionsDb()`:

**Bug 1 (wrong property):** When `parent.type === "data_source_id"`, the code read `parent.database_id` which does not exist on a data_source parent object. Fixed to read `parent.data_source_id`.

**Bug 2 (wrong ID type):** The comparison was against the configured DATABASE ID (`sessionsDbId`), but the page's `parent.data_source_id` contains a DATA SOURCE ID — a completely different identifier. Fixed by resolving the DATA SOURCE ID via `resolveDataSourceId(sessionsDbId)` before comparison.

## 3. resolveDataSourceId Export

`resolveDataSourceId` was a private function at `src/lib/notion/queries.server.ts:33`. Added the `export` keyword. No other behavior changed — caching, error handling, and conversion logic are identical.

## 4. validateSessionBelongsToSessionsDb Final Logic

```typescript
async function validateSessionBelongsToSessionsDb(sessionId: string): Promise<boolean> {
  const clientResult = createNotionClient();
  if (!clientResult.ok) return false;

  const sessionsDbId = getNotionConfig().sessionsDatabaseId;
  if (!sessionsDbId) return false;

  try {
    const expectedDataSourceId = await resolveDataSourceId(sessionsDbId);
    const page = await clientResult.client.pages.retrieve({ page_id: sessionId });
    const parent = "parent" in page ? page.parent : undefined;
    if (!parent) return false;
    if (parent.type === "database_id") {
      return parent.database_id === sessionsDbId;
    }
    if (parent.type === "data_source_id") {
      return parent.data_source_id === expectedDataSourceId;
    }
    return false;
  } catch (error) {
    // ... existing error handling (unchanged)
  }
}
```
